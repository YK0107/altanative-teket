# 合意事項・仕様変更メモ

`spec-v0.1.md` に対する合意事項。**矛盾する場合はこのファイルを優先**する。

最終更新: 2026-11-15

## 1. 前提

| 項目 | 決定 |
|---|---|
| 規模 | 1公演・数百〜最大約2,000席。発売開始時の同時アクセス数百を想定 |
| 公演数 | **1公演のみ**（データ上は `event_id` を保持し、次回公演に再利用できる形にする） |
| 会場 | 東京芸術劇場 コンサートホール（座席表: `assets/geigeki-concert-hall-seatmap.pdf`） |
| 席 | **指定席**。購入者が座席表から座席を選ぶ |
| 実行基盤 | **AWS**（v0.1 の構成どおり）。Cloudflare（Workers + D1）の無料構成も検討したが一旦見送り |
| IaC | **Terraform**（v0.1 の CDK から変更）。main へのマージ時に GitHub Actions から自動 apply |
| 環境（dev） | GitHub Pages のモック環境は必要になったら作る。開発中はモック画面のスクショで確認 |

## 2. 座席・券種・価格

- 座席表：1階／2階／3階をタブで切り替える。2階バルコニー（LB/RB）は2階タブに表示する
- 座席データ：PDF から自動抽出（`tools/seatmap/extract.py`）。通常席は1階676・2階683・3階640・計1,999席で、PDF 内訳表と一致することを確認済み
- **販売対象は計2,003席**（通常1,999席＋車椅子スペース4席）。管理画面の総数もこの値
- 券種（**暫定。後から変更可能にする**）

| 券種 | 対象 | 価格 |
|---|---|---|
| S席 | 1階・2階 | 1,000円 |
| A席 | 3階 | 500円 |
| 車椅子席 | 1階O列脇の常設スペース 2カ所×2台＝4席 | 500円 |

- 車椅子席は介助者席なしで、ネット販売する。C/D列の取り外し式の席は通常席として扱う
- 1注文の上限は **10枚**。複数の座席を選択できる

## 3. クーポン

- コードは約100個。どのコードも効果は同じ
- **何度でも使える**（使用回数の制限なし）
- **1枚あたり500円引き**。オンライン購入では注文内の全席に適用する
- 合計が0円の注文は **Stripe を通さずに直接発券する**（A席・車椅子席にクーポンを使うと0円になるため）
- 割引は高い席から適用する（当日券で一部の枚数だけに使う場合に影響）

## 4. 購入者

- 入力項目：氏名、メールアドレス（確認用に2回入力）。**電話番号は取らない**
- 会員登録はしない（ゲスト購入）
- 譲渡・名義変更の機能は作らない。QR（チケットURL）を渡すことでの受け渡しのみ可
- キャンセル・返金は不可（公演中止時のみ Stripe ダッシュボードから手動で返金）

## 5. チケット・メール

- メールには **QR画像を貼り付ける**（CID方式のインライン画像。SES の raw 送信を使う）＋チケットURL `/t/{token}`
- 決済完了画面にもチケット（QR・リンク）を表示する。キャリアメールに届かない場合の対策
- QR の中身はチケットURL（`.../t/{token}`）。受付ではトークン部分を取り出して照合する

## 6. 当日

- **当日券（会場での現金販売）を作る**。スタッフ画面で座席を選び、クーポンの枚数を入力して販売を確定する。確定と同時に入場済みにする
- **ネット販売も当日まで継続する**
- スタッフは**受付URL（キー付き）のみ**で利用する。個別アカウントは作らない
  - URL は `/staff#key=...`。フラグメントで渡すことでアクセスログに残さず、読み取り後は URL から消す。キーはローテーションできるようにする
- スタッフ機能：QR受付（OK／使用済み／無効）、名前検索から注文単位でまとめて入場、当日券の販売

## 7. v0.1 からの設計変更（合意済み）

- **在庫は座席単位で管理する**：1席を1レコードとし、状態は AVAILABLE / HELD / SOLD
  - 予約時は TransactWriteItems で「全席が AVAILABLE なら HELD にする＋注文作成」を一括で行う（10席＋注文＋α で上限100件に収まる）
- **Webhook の冪等性**：PAID への更新とチケット作成を同じトランザクションで行う。メール送信は `email_sent` フラグで別管理し、再試行できるようにする
- **購入中断時は即解放**：`/purchase/cancel` で Stripe の `sessions.expire` を呼び、座席をすぐに解放する
- **定期回収**：EventBridge で定期実行し、期限切れなのに PENDING のまま残った注文を回収する（Webhook が届かなかった場合の保険）
- **座席状況 API の負荷対策**：座席レイアウトはフロントに静的に持たせる。API は売れた席・仮押さえ中の席のIDだけを返し、CloudFront で数秒キャッシュする
- **同一オリジン化**：CloudFront で `/api/*` を API Gateway に振り分け、CORS を不要にする
- **秘密情報**：Stripe の鍵などは SSM に手動で登録し、Terraform は参照のみにする（state に値を残さない）
- **AWS 新規アカウント**：Lambda の同時実行数の上限緩和を公開前に申請する。SES のサンドボックス解除と Stripe の審査も早めに申請する
- 日時は UTC で保存し、表示は JST
- **0円注文の照会**：`order_id` だけでは照会できないようにし、別の秘密値 `order_key` を必須にする
- CSV 出力では、数式として扱われる先頭文字（`= + - @`）をエスケープする（CSVインジェクション対策）
- クーポンコードはサーバー側で trim・大文字化して照合し、枚数は整数か検証する
